# 养护材料流水线

把养护材料的**示例数据准备 → 后端接口自检 → 前端构建检查**串成一条可重复执行的流程，
每次运行都给出各环节的通过情况；某个环节失败时会标明是**数据问题**还是**构建问题**，
并可以只重跑该环节，不必整条重跑。

## 使用

```bash
make check            # 跑全部环节
make check-seed       # 只重跑「示例数据准备」
make check-api        # 只重跑「后端接口自检」
make check-frontend   # 只重跑「前端构建检查」
```

也可以直接调用编排脚本：`python3 scripts/run_pipeline.py [--only seed|api|frontend]`。

## 环节说明

| 环节 | 脚本 | 检查内容 | 失败归类 |
| --- | --- | --- | --- |
| 示例数据准备 | `material_seed_check.py` | 种子数据能加载进内存仓库；材料编号/材料名称/规格型号非空、结存数量为非负数字；种子数据 ↔ services ↔ routers ↔ 前端页面的字段口径一致 | 数据问题 |
| 后端接口自检 | `material_api_check.py` | 临时起真实服务（随机空闲端口，不影响 8000 开发端口），逐项调列表/筛选/明细/登记/状态流转/导出/分页保护 | 返回内容不符为数据问题；服务起不来、状态码异常为构建问题 |
| 前端构建检查 | `npm run build` | vue-tsc 类型检查 + vite 构建 | 构建问题 |

环节脚本退出码约定：`0` 通过、`2` 数据问题、`3` 构建问题，编排脚本据此归类汇总。

接口自检在临时进程里做登记与状态流转，改动只留在该进程内存中，
不会污染开发环境的数据；现有养护材料页面与查阅方式不受影响。
